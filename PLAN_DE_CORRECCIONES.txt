    Archivos: backend/app/routers/auth.py (send_verification_code)

    Problema: el endpoint devuelve el codigo en el JSON de respuesta y el

    Archivos: frontend/src/components/Auth/AuthModal.jsx

    Hacer:

        empresas. Quitar ese modo.
      - admin.py (prompts): solo usuarios con role == "admin".
      - Eliminar GET /api/v1/auth/email-status y
        GET /api/v1/auth/check-email-delivery, exponen configuracion interna.

2. BASE DE DATOS E INFRAESTRUCTURA
=====================================================================

2.1 Quitar el fallback silencioso a SQLite
    Archivo: backend/app/database.py, lineas 18-28
    Problema: si Supabase no responde en 2 segundos, la app arranca con una
              SQLite vacia sin fallar. En Render un parpadeo de red pierde
              datos en silencio.
    Hacer:
      - Si DATABASE_URL es Postgres y no conecta, la app debe fallar al
        arrancar con un error claro.
      - SQLite solo cuando DATABASE_URL apunta explicitamente a sqlite.
      - Subir connect_timeout a 10 y agregar pool_pre_ping=True.

2.2 Ruta absoluta para SQLite en desarrollo
    Archivo: backend/app/config.py, linea 14
    Problema: "sqlite:///./chambachat.db" es relativa al directorio desde
              donde se ejecuta. Por eso existen tres .db distintos (raiz,
              backend/, test.db) con datos diferentes.
    Hacer: construir la ruta con os.path.dirname(__file__) para que siempre
           apunte a backend/chambachat.db. Borrar chambachat.db y test.db
           de la raiz del proyecto.

2.3 Adoptar Alembic para migraciones
    Archivo: backend/app/main.py, lineas 16-100 (auto_upgrade_schema)
    Problema: dos listas de 30 ALTER TABLE identicas (Postgres y SQLite)
              que corren en cada arranque con except: pass.
    Hacer:
      - pip install alembic, alembic init backend/alembic.
      - Generar la migracion inicial desde los modelos actuales.
      - Borrar auto_upgrade_schema() y Base.metadata.create_all() de main.py.
      - En build.sh agregar: alembic upgrade head.
      - Cada cambio de modelo a futuro = una migracion nueva.

2.4 Actualizar o eliminar postgres_schema.sql
    Archivo: backend/scripts/postgres_schema.sql
    Problema: tiene 5 tablas; los modelos tienen 12. Nadie puede usarlo.
    Hacer: eliminarlo una vez que Alembic sea la fuente de verdad, y
           actualizar el README para que apunte a Alembic.

2.5 Relacion real entre Job y Company
    Archivo: backend/app/models.py, clase Job
    Problema: empresa_id es un entero con default 1 sin ForeignKey. Toda la
              asociacion empresa-vacante es por el string empresa_nombre.
    Hacer:
      - empresa_id = ForeignKey("companies.id"), nullable=True mientras
        se migran datos.
      - relationship Job.company y Company.jobs.
      - POST /api/v1/jobs debe recibir company_id y validar membresia.
      - Filtros de jobs.py y Smart Link (?empresa=) deben usar company_id
        o un slug de empresa, no coincidencia de texto.

2.6 Identificar usuarios por email o id, nunca por nombre
    Archivos: backend/app/routers/auth.py linea 107
              backend/app/services/chatbot_engine.py linea 211
    Problema: se busca User por nombre. Dos "Juan Garza" se fusionan.
    Hacer: quitar las busquedas por User.nombre. Usar user_id de la sesion
           de chat o email. Si no hay ninguno, crear usuario nuevo.
